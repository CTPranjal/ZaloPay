How ZaloPay and CleverTap keep real customer data in Vietnam

5 November 2026 · Prepared by CleverTap Solutions Engineering for ZaloPay product, marketing, growth and technology teams

Real emails and phone numbers stay in ZaloPay's vault in Vietnam. CleverTap works only with tokens. The real value is brought back only inside ZaloPay's own dispatcher, just long enough to hand the message to the delivery provider.

Swap real values for tokens

Led by ZaloPay

When a user registers, logs in or updates a profile, ZaloPay's backend swaps the real email and phone for tokens before anything goes to CleverTap. This all happens inside ZaloPay.

What happens

  • ZaloPay1aThe app sends the real email and phone to ZaloPay's backend, as it does today.
  • ZaloPay1bThe backend calls the vault's Tokenize API over the private network. The vault encrypts the real value with AES-256, using a key from ZaloPay's own key management, and stores the pair.
  • ZaloPay1cThe vault returns a token shaped like an email or a phone number.
  • ZaloPay1dThe backend returns tokens to the app for every CleverTap-bound field.

Where the real value is visible

CleverTapNOT VISIBLE
ProviderNOT VISIBLE

The app never calls the vault directly. Only ZaloPay's backend does.

ZaloPay builds

  • Change register, login and profile-update APIs to call Tokenize and return tokens
  • Tokenize batch, file and server-to-server uploads before they reach CleverTap
  • Tokenize all existing user records once, then upload the tokens
  • Get an access token for vault calls (OAuth2 client credentials)
  • Plan a refresh path: expired tokens must be tokenized again

CleverTap provides

  • The Tokenize and Detokenize API contract and documentation
  • CT Vault software, if ZaloPay picks it
  • No SDK change is needed, because tokens keep the shape of emails and phone numbers
  • Tokens are stable: the same value for the same user gives the same token

A campaign sends

Hand-off between both

Example: a push or SMS campaign runs on 12 Dec 2026. CleverTap decides who gets it using tokens. ZaloPay's dispatcher turns the token back into the real value and hands the message to the provider.

What happens

  • CleverTap3The campaign triggers and finds qualifying users from tokens and non-PII data.
  • CleverTap4CleverTap builds the message with tokens in a placeholder and posts it to ZaloPay's dispatcher over HTTPS.
  • ZaloPay5aThe dispatcher sends the tokens to the vault's Detokenize API, in batches.
  • ZaloPay5bThe vault returns the real values. This stays inside ZaloPay's network.
  • ZaloPay6aThe dispatcher sends the message with the real value to the provider.

What changes for marketing, product and growth

Because CleverTap holds tokens instead of real values, a few everyday actions work differently.

Works as usual
  • Segments, campaigns and journeys on non-PII fields such as city, device and behaviour
  • Email, SMS, WhatsApp and push personalisation, because tokenized values are resolved just before the message is dispatched
  • Remarketing audiences on Meta, TikTok and Google Ads
  • In-app, inbox, native display and web push campaigns. They do not need a real value to run. A token is only involved when a campaign qualifies users on a tokenized field, for example one specific person by email.
  • Campaign and journey reports and analytics
Works differently
  • Segments on tokenized fields match the token, not the real value. To target one person by email or phone, use their token.
  • You cannot look up a user by email or phone in the dashboard
  • Message preview does not show the real value
  • De-duplication is not supported in the current release
  • Each send adds a little time for the vault lookup
  • Exports contain tokens, as designed. Plan for this early if ZaloPay relies on exports.
  • Tokens expire and must be tokenized again
Not available or limited
  • Personalising online channels (in-app, inbox, native display, web push, pop-ups) with a tokenized value. This is by design: it would mean resolving the real value before it reaches the device, and the real value never reaches CleverTap. Use non-PII fields for on-screen personalisation.
  • Email by SMTP, and providers outside the supported list
  • Webhooks
  • Message archiving with tokenization
